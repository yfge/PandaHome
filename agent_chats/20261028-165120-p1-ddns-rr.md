## Summary

Fix P1 DDNS updates that omitted the original RR when reusing the existing
Aliyun DNS service. The official [UpdateDomainRecord contract](https://help.aliyun.com/en/dns/api-alidns-2015-01-09-updatedomainrecord)
requires RecordId, RR, Type and Value. Keep the change limited to DDNS request
construction and verify the actual official SDK request at the transport boundary.

## Changes

- `api/src/app/services/access/dns.py`: pass the original `rr` into
  `DomainRecordUpdateRequest(rr=rr, type=record_type, value=value)`.
- `api/tests/test_access_dns.py`: add five table-driven cases for A, AAAA and
  CNAME value changes, A-to-CNAME and CNAME-to-A transitions. Each case calls
  the real `AliyunDNSService` and captures its official
  `UpdateDomainRecordRequest`, checking all four required fields. Only SDK
  transport is replaced; the update method and request construction are real.
  Repeating the same desired input must issue no additional SDK update.
- `agent_chats/20261028-165120-p1-ddns-rr.md`: focused defect, verification and
  coordinator handoff record. Existing parallel work and the shared index remain
  untouched by this agent.

## Outcome

The request now includes the unchanged multi-label RR together with RecordId,
Type and Value. All five new regression cases reproduced missing `RR=None`
before the fix and pass after the one-line correction. Existing DNS conflict,
pagination and domain API tests also pass. This is local SDK-boundary evidence;
the isolated unit subtask made no provider request. The root owner subsequently completed the real DDNS lifecycle below.
