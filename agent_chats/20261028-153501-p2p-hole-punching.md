# P2P hole punching

## Summary

Implement the requested NAT hole punching using native frp XTCP and optional STCP
fallback. Keep private client-assisted access separate from existing public
UPnP/DDNS and the concurrent managed-public-access work.

## Changes

- `api/src/app/models/p2p_service.py`, `api/src/app/schemas/p2p.py`,
  `api/src/app/services/p2p.py`: persisted TCP targets, per-service credentials,
  provider/visitor configuration, isolated process supervision and recovery.
- `api/src/app/services/relay.py`: add an overridable rendering method while
  preserving the existing public-relay behavior and process owner; add a command
  hook whose default still executes frpc directly.
- `api/src/app/services/process_guard.py`: P2P-only child supervisor checks the

- `api/src/app/routers/p2p.py`, `api/src/app/main.py`, `api/src/app/config.py`:
  active-admin API, secret-free status, credential downloads and lifecycle wiring.

  `api/alembic/versions/031aa92bee52_create_p2p_services.py`: model registration
  and migration generated with `cd api && python -m alembic revision -m 'create p2p services'`.
- `api/tests/test_p2p_api.py`, `api/tests/test_p2p_service.py`,
  `api/tests/test_p2p_migrations.py`, `api/tests/test_p2p_native.py`:

- `web/src/app/p2p/`, `web/src/components/p2p/`,
  `web/src/i18n/locales/p2p/`, `web/src/components/layout/main-nav.tsx`:

- `api/.env.example`, `README.md`, `README.zh.md`, `api/README.md`,

## Outcome

Implemented XTCP with optional encrypted STCP fallback, persisted intent,
credential export, active-admin API and localized UI. Provider process state is
explicitly separate from successful signaling, a working P2P tunnel or externally
verified access. The visitor is restricted to loopback and requires frpc on the
remote device. Each state directory supports one backend process/worker.

Independent review found a reproducible crash-recovery defect: after forcibly
ending the backend, the old frpc could survive and continue serving a visitor
after a replacement manager disabled the service. The P2P parent guard fixes
that path; a native subprocess regression verifies actual connection revocation.
Review also fixed relative/home CA paths before frpc changes working directory,
and aligned the frontend service-name limit with the backend's 80 characters.
